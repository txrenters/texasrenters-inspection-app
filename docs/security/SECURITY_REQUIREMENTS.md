# Security Requirements

The backend validates environment configuration, applies secure headers and allowlisted CORS, emits request IDs, sanitizes errors, validates DTOs/MIME/size, and checks organization ownership and assignment. Supabase access tokens are signature-, issuer-, audience-, and expiry-validated. The trusted application profile, organization, and roles are loaded from PostgreSQL; JWT metadata and frontend role input are never authorization sources. Provider/webhook verification is abstracted; event IDs are idempotent. Sensitive review actions are audited.

Never log tokens, secrets, tenant personal information, full transcripts, video content, or private AI prompts. The frontend contains only public Supabase configuration and sends access tokens to the REST API. Mobile sessions use SQLite-backed storage because complete sessions can exceed SecureStore's value limit. Mock authentication requires `USE_MOCK_AUTH=true` and is rejected in production. Production still requires signed video playback, distributed rate limiting, Sentry filtering, managed secret storage, and confirmed retention/deletion policies.
